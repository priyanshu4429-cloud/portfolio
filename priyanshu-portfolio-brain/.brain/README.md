# Priyanshu Kumar — Portfolio Specification (`.brain`)

This directory is the implementation-ready product specification for Priyanshu Kumar’s developer portfolio. It is documentation only: no portfolio site has been built by producing these files. The materials are intended to be handed to a future implementation agent together with the actual source repository and approved assets.

## Reading order

1. `PROJECT_MASTER.md` — scope, verified facts, exclusions, and decision rules.
2. `DESIGN_SYSTEM.md`, `WEBSITE_ARCHITECTURE.md`, `CONTENT_STRATEGY.md` — experience, structure, and copy.
3. `PROJECT_DOCUMENTATION.md` — project cards and attribution boundaries.
4. `TECH_STACK.md`, `ASSET_MANIFEST.md`, `ANIMATION_SPEC.md` — implementation choices and media treatment.
5. Responsive, accessibility, performance, SEO, and quality documents — cross-cutting requirements.
6. `MANUS_EXECUTION_PLAN.md` — implementation sequence and handoff protocol.

## Authority and conflict resolution

`PROJECT_MASTER.md` is authoritative for scope, personal facts, project attribution, and non-fabrication. `DESIGN_SYSTEM.md` owns visual tokens; `WEBSITE_ARCHITECTURE.md` owns section order and structure; specialist documents own their named concerns. If two documents conflict, preserve factual accuracy and accessibility first, then performance, then the visual preference; record material changes in `CHANGELOG.md`. Unknown details must remain `[NEEDS CONFIRMATION]`, not be guessed.

## Status vocabulary

- **Verified in supplied brief**: may be represented as stated.
- **[NEEDS CONFIRMATION]**: require owner confirmation before publication.
- **Placeholder**: intentionally withheld; do not render as a made-up fact.
- **Proposed**: design/technical recommendation, not a claim about existing implementation.

## Change record

Record decisions, confirmed assets, verified details, and scope changes in `CHANGELOG.md`. Date entries when known; do not invent dates.
