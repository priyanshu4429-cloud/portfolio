# SEO and Sharing Strategy

## Search intent and identity

Present an accurate personal developer portfolio, not an agency or established company. Use a unique page title such as “Priyanshu Kumar — Developer & AI Builder” and a concise description grounded in confirmed information. The exact title/description should be reviewed by the owner. Avoid keyword stuffing and unsupported seniority or expertise claims.

## Technical requirements

- Produce crawlable initial HTML for the primary content; do not require client-only animation to reveal text.
- Set canonical URL only after the final Vercel/custom domain is confirmed [NEEDS CONFIRMATION].
- Set Open Graph and social card metadata from approved portrait/brand assets and accurate copy. Do not ship a temporary or invented domain.
- Add favicon/manifest assets only after a final mark is approved. Use a descriptive alt/title where applicable.
- Include a sitemap and robots rules appropriate to the final domain if the site has multiple public routes; for a single static route, avoid unnecessary infrastructure.
- Ensure correct 200/404 behavior, HTTPS, and descriptive project link text.
- Do not add Organization/Person structured data with unverified fields. If Person JSON-LD is added, verify every value and URL with the owner and keep it consistent with visible copy.

## External links and privacy

Open external links in the same tab by default; if opening a new tab is needed, communicate it and apply `rel="noopener noreferrer"`. No analytics or tracking without an explicit privacy decision. Public email/phone display is a consent/freshness issue; use supplied details only after owner reconfirms.

## Prelaunch verification

Check page title and description, social preview rendering, canonical URL, indexability, live demo/repository links, spelling, and claim consistency. Do not claim search ranking, indexing, or traffic results without evidence.
